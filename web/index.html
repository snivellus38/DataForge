One

So where did the rule go?

Nothing in the model changed. The weights are identical — same hash, byte for byte. Yet removing one line changed the answer. Whatever held that rule was written somewhere else, and thrown away when the line disappeared.

It was written here: a matrix called σ, built fresh on every forward pass. Each token adds one rank-one update to it, and the model answers by reading it back.

σt = σt−1 + rope(K)t ⊗ Vt outt = σt⊤ rope(Q)t write, then read. That is the whole mechanism.

Two

Is any of this actually running?

A convincing animation would look identical. So here is a check an animation cannot fake.

The official bdh.py computes attention the parallel way — a full token×token score matrix, masked causal. We compute the same layer the recurrent way, accumulating σ token by token. If σ were decoration, the two would disagree.

max | parallel − recurrent | —

break it:

Only one of those three breaks it — and which one is the lesson. Softmax normalises each score against every other, so no fixed-size running sum can reproduce it: you have to keep every past key. That is precisely why a Transformer needs a KV cache that grows with context.

The other two survive. Tying Q to K and clamping activations non-negative buy something different: they make σ readable as a matrix of synapses over one basis of neurons. Not constant memory — legibility. Hold on to that, because it is about to cost us.

Three

Then why does it ever forget?

A fixed-size state must fill up. The obvious guess is that it holds about as many rules as it has rows — 256 here. The obvious guess is wrong, and being wrong about it is the most useful thing on this page.

Below, k bindings are written into a state of exactly the same shape and read straight back. No model, no training — just the geometry.

mean overlap, ReLU'd keys —analytic 1/π = 0.318
mean overlap, signed keys —orthogonal on average
retrieval at k = 32 —

Non-negative vectors cannot point away from each other. Two ReLU'd Gaussians overlap by 1/π on average, every pair, unavoidably — so each new binding smears across the ones already stored. Let the keys go negative and they become orthogonal on average; the same state then holds bindings past its own rank.

Capacity is bounded by overlap, not by size. The ReLU that makes BDH inspectable is the same ReLU that makes it forget sooner.

Four

Where this lives in BDH-CQ

Everything so far ran on a model we trained ourselves. The architecture is Pathway's Dragon Hatchling, used unmodified; the weights are ours, and small. So what does any of it say about the real system?

BDH-CQ writes demonstrations into a contextual memory S with frozen parameters. The technical report gives the update in its general form — and then names the special case that linear attention realises:

St = Uθ(St−1, Dt)general form St = St−1 + Uθ(Dt)the special case arXiv:2608.09888 §3.2, p.3 — “linear attention being the conceptually simplest standalone realization… capturing the special case”

That lower line is the shape of the recurrence you have been watching all along. σt = σt−1 + rope(K)t ⊗ Vt is an instance of it. Not an analogy — the additive accumulation the report singles out is exactly what softmax-free attention with K tied to Q computes, which is why removing the softmax above broke the equivalence and nothing else did.

One correction worth making. It is tempting to say BDH-CQ’s memory is additive accumulation. The report does not say that. Equation (1) is the general Uθ; additive accumulation is named as a special case, and the actual update rule is proprietary. We can show you the special case because it is what the public code computes. We cannot show you theirs.

Answering happens in a second state. A workspace H is refined R times against the finished memory, and only the last step is decoded — reasoning with no verbal trace:

H0 = Eθ(x★, SK) Hr+1 = Fθ(Hr, SK)same θ, applied R times ŷ = Gθ(HR) arXiv:2608.09888 §3.3, eqs. (2)–(4), p.3. The report never states a value for R, and never says what changes between its effort levels.

Our model has the same shape in miniature, for a reason that surprised us: the vendored bdh.py is weight-tied across layers. Its encoder, encoder_v and decoder are built once and reused every iteration, so n_layer is not depth — it is a count of how many times one operator runs. The same θ, applied L times.
